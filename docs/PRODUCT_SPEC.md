# Product specification

Learning OS turns a learner's own incremental material into a citation-backed teach → check → calibrated review loop. It serves independent adult learners, certification preparation and university study. Its claim is a distinctive workflow, not proof that it invented retrieval practice or that this particular application has measured educational efficacy.

## Primary journey

Home → create/open Collection (Explore collection) → Add Material → processing status → Outline → select titled sections from multiple materials → Go (create scope revision) → Study one concept → confidence before answering → Reviewer feedback → visible scope progress → spaced Review → persistent weak-spots/history. Resume returns to the same scope revision and next pending concept. Ingestion never auto-enrolls all titles.

## Learning invariants

1. A title is a Chunk with a user-facing heading. A concept is a smaller testable idea beneath it. A scope stores selected chunk IDs plus order and revision. Selected titles form 100%; unselected/late-uploaded titles do not count.
2. `percent = round(100 * completed_titles / selected_titles)`; an empty scope returns 0 with a 'Choose titles' state and cannot start a session. A title can occur once per scope. A completed title remains completed historically; later review failure flags weak/review-needed status rather than rewriting old progress events.
3. Reorder materials and titles persistently within their permitted parent; sorting uses explicit positions and stable IDs. Cross-material selection is supported; moving a title to another material is not silently allowed. Provide up/down controls and keyboard drag alternatives.
4. Teach one concept briefly from cited excerpts, then ask one recall/explain/apply check. The learner reports confidence 1–5 before feedback; do not expose the expected answer or grading rubric in public payloads until submission. Retrieval question wording must not contain the expected answer. A teaching paragraph can explain the idea: use application or later cold recall to assess transfer instead of merely copying that paragraph.
5. Reviewer returns correctness, missing/wrong parts, guessing/uncertainty signals, calibrated feedback, title decision and source-supported rationale. Server validates cited concept IDs, selected scope membership and critical-concept coverage before accepting completion. Correct confidence alone is not enough; one sub-concept must not complete a broad title. No fixed streak or three-correct shortcut. Stop retesting already demonstrated concepts.
6. Preserve uncertainty. A confident wrong answer triggers correction and weak status. A correct low-confidence answer prompts one targeted follow-up or later review. A confident justified answer can complete a narrowly scoped title when critical concepts are adequately demonstrated. Speech hesitation by itself is never evidence of low ability or guessing.
7. Confidence normalized as `(rating - 1) / 4`; assessed correctness as 0/1, unresolved uncertainty excluded from both matched aggregates. The dashboard uses mean confidence and accuracy for the same answered-attempt window, sample count, signed gap and optional Brier score. Tiny samples are labeled 'Not enough history'; never compare different windows.
8. Review starts at +1 day after completion. Successful reviews advance to 3/7/14/30 days from the current attempt; failures reset to +1 day. Use persisted UTC instants and the learner's IANA zone for 'today'. Deduplicate completion events and scheduler runs. Do not make skipping due work magically advance the ladder.

## Ingestion and provenance

PDF page numbers (1-based); Markdown/text/RST heading and line range; DOCX heading and extracted paragraph/table-row range; XLSX workbook/sheet/cell range; CSV/TSV row and columns; JSON/YAML key path and source line range; log line range; photo filename/section and optional bounding box; web canonical URL, snapshot date and paragraph; captions video ID, start/end seconds and transcript language. Every citation points to an immutable extracted source revision and exact source excerpt, not a model-invented page. Unsupported PDF OCR cases get a processing/needs-attention state and a photo/OCR adapter route. No silent guessed handwriting. Tiny sections may contain fewer than three concepts rather than fabricate 3–8.

Ingestion is asynchronous, with queued/running/succeeded/needs-attention/failed states. Content hashes/provider version IDs prevent duplicate ingest; changed files create revisions and require explicit scope update. A job failure retains the prior valid material and offers a retry. Explain unreadable, encrypted, empty, oversize, unsupported and no-captions outcomes gently. Original study fixtures must be license-clear; uploads remain private.

### Explicit material deletion

An authenticated learner can permanently delete one Material after a full-consequences confirmation. Deletion removes all of its source revisions, private originals when no other owned revision references the same blob, extracted Chunks, Concepts, Citations, related source receipts, scope entries, assessments, progress events and review state. The active scope becomes a new immutable revision containing only the surviving selected titles; other materials' learning history is preserved. Sessions containing deleted material are interrupted and their source-derived turns/summaries are erased. For Drive-backed material, delete each exact remote file only after verifying its current parent is the bound Collection folder and receiving provider confirmation. A permission/network failure leaves app data intact in a retryable/attention state. Explicit deletion is the only exception to source-revision/history retention; backup copies expire under the configured backup retention policy and are disclosed in the confirmation.

### Coherent retrieval and original-document verification

Prepare material before study: accept the upload, durably retain the original, extract readable source text, group related paragraphs under actual headings into bounded chunks, then expose titles for learner selection. Split large sections at paragraph/sentence boundaries; preserve source order and exact page/line/sheet/cell coordinates. Do not mix unrelated topics to satisfy a fixed chunk count or invent missing text. Model training/fine-tuning is not implied by this preparation stage.

Every study explanation, check and assessment uses excerpts from the selected immutable source revision. Citation inspection shows the original excerpt, locator and an owner-authorized download of the original document, allowing a learner to verify or dispute a claim. Keep citations valid after chunk subdivision; absence of supporting source means clarification/needs-attention, not fabricated content. Retrieval uses persisted owned chunks/concepts; latency improvements require measured evidence. Study teaches before checking; scheduled Review remains cold recall.

### Format-aware teaching windows (`source-excerpts-v3`)

Use the useful CustomerSupport parsing behavior without importing its chat/retrieval runtime: OpenAI `tiktoken`, sentence-aware 160-token windows and 20-token context overlap. Preserve each actual source section as the learner-selectable `Chunk`; bounded windows and their `Concept` records remain beneath that title, so this parser never expands an existing scope denominator. The overlap supplies teaching/citation context, not a second completion requirement: assess each non-overlapping concept core once.

- PDF: extract in page layout order, normalize repeated visual whitespace, promote only conservative short ALL-CAPS headings, then split within each original page/heading. Use PDF bookmarks when present for chapter grouping. A durable worker processes the original PDF in resumable 40-page batches, up to 1,000 pages total and 64 MiB extracted text; image-only pages use the existing server vision boundary and keep global 1-based page, heading and OCR provenance. Unavailable or unreadable OCR remains needs-attention until reviewed.
- Markdown: split at heading hierarchy and preserve heading paths. DOCX: walk paragraphs and tables in body order; Word heading styles become section boundaries and table rows stay with their section. RST underlined headings and conservative ALL-CAPS plain-text headings become boundaries.
- CSV/TSV and XLSX: one source row is one indivisible teaching unit with column headers repeated; preserve row, sheet and cell locators. JSON/YAML: flatten leaves with their full key path for teaching, but citations must still quote exact original source text and identify the key path/line. Logs use sentence boundaries and line locators.
- HTML file uploads remain unsupported; safe public HTML continues through the URL source adapter. Do not execute macros, scripts, archives or source instructions. Parsing is deterministic/local; all external model calls, including OCR or any optional context help, go through `backend/app/llm.py`.

## Ingestion size and completeness limits

Publish the same server-enforced source limits in Add Material and in API errors: 20 MiB maximum per uploaded file; PDF up to 1,000 pages processed as resumable batches of 40 pages and 64 MiB extracted text; learner page corrections up to 2 MiB each, within the same aggregate text cap; text/Markdown/RST/log/CSV/TSV/JSON/YAML up to 2 MiB; CSV/TSV and XLSX/XLSM up to 10,000 parsed cells; DOCX/XLSX/XLSM expanded size up to 64 MiB and 1,000 archive entries; structured JSON/YAML nesting depth 64 and 10,000 leaf values; JPG/PNG up to 40 megapixels; fetched public pages up to 2 MiB and URLs up to 4,096 characters; permitted captions up to 10,000 segments and 2 MiB of text. Source extraction is bounded to 10,000 teaching windows per source revision. Limits are configurable only when the running service enforces the corresponding safe bound; the UI must not advertise a larger setting than the parser accepts.

For large PDFs, keep the single original Material and immutable source revision while a durable worker processes page ranges in 40-page batches. Preserve global 1-based page numbers, bookmark/heading paths, per-page extraction method, counts, and status across retries/restarts. The page manifest distinguishes text-extracted, OCR-extracted, blank, review-required, corrected, and failed pages. Do not mark a revision ready until all pages have an accepted result. OCR string output is not a perfectness guarantee: heuristics flag suspiciously empty/garbled output and users can inspect the original page beside extracted text, correct/accept the page, and resume final chunking. Page corrections create traceable extraction metadata without modifying the retained original.

New parser output is stamped `source-excerpts-v3`. Existing revisions, citations, selected scopes, completion history and review state remain immutable. Any reprocessing creates a new source revision and requires an explicit learner scope update. Generated context may help locate or teach a passage, but only an original excerpt can be citation evidence.

## Source integrations and channels

Connected Collections automatically provision/reconcile an app-managed Drive folder. UI originals and managed web/captions receipts are saved in that folder; manual drops are discovered by bounded polling/checkpoints and manual Sync through the same deduplicated ingestion pipeline. Resolve the parent folder from persisted Collection identity. Use explicitly consented scoped Drive write/read access and verify manual-drop visibility; unconnected demo/local mode is labeled. See DRIVE_INGESTION for provisioning, upload confirmation, retries, scope consent, disconnect and token deletion. MCP is used only where an actual deployed server exposes the needed listing/download tools; runtime OAuth/direct API adapter is labeled honestly otherwise. Public URLs never fetch login-only/paywalled content. Captions-only YouTube: official authorized transcript route or permitted source; unavailable captions return needs-attention, never a fabricated transcript or video-watch claim.

Photo input supports clear JPG/PNG; request a retake when unreadable. Voice Study is a two-way tutor conversation: the tutor can speak its cited teaching, question and Reviewer feedback; the learner can answer by microphone, inspect/edit the transcript, set confidence and submit through the same grading path as typing. Targeted cited follow-ups are speakable, with at most three learner voice turns. Microphone refusal/browser incompatibility/provider outage leads to explicit typing; provide replay and stop controls, and stop audio on navigation. Raw audio is not retained by default. Gmail read-only ingestion is optional after explicit permission; email sending/reminders and audio/video upload transcription are excluded.

## Required interface states

Every screen has initial loading, empty, ready, retryable-error and unavailable-integration behavior. Authentication-required screens name the configured identity provider: the current local option is Google account sign-in, not Gmail content access. Future Apple/Microsoft options remain visibly unavailable placeholders until each provider is actually configured. Session screens also have pending generation, awaiting confidence/answer, reviewing, finished and interrupted/resumable states. Live failure cannot fall back to fabricated success. Demo data carries a visible 'Offline demo — sample material' marker. Production has no debug completion controls or unauthenticated demo principal.

Accessible names, visible focus, accessible source links, reduced motion, 44px touch controls, keyboard reordering, focus trap/restore on dialogs and mobile drawer, clear confidence labels and error announcement are required. Dashboard accessibility statements in its README are claims to audit, not a substitute for testing.

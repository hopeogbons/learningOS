# Security and privacy requirements

Protect learner materials, answers and connected accounts. This checklist is tied to concrete implemented surfaces; it is not a claim of certification.

- Production OIDC validates issuer/audience/signature, state, nonce and PKCE; secure opaque cookies; session expiry/revocation; CSRF protection on mutations. Demo user/fake provider require non-production mode. Auth failure is tested, not handled by trusting a browser user ID.
- Access control on Collection, source, citation, scope, session, history, job, search and object storage. A second learner's IDs never reveal metadata. Database tests and S3 key authorization tests exercise this explicitly.
- Secrets stay server-side in secure environment settings or encrypted credential storage; never `NEXT_PUBLIC_*`. Inspect names/presence only. In this cloud configuration flow, reserved `OPENAI_*` names cannot be newly declared: use `LEARNING_OS_API_KEY`, passing it explicitly to OpenAI client initialization. Normal external hosts may use their own secret mechanism. Do not copy developer Git/Drive credentials into runtime code.
- Public URL fetch prevents SSRF: only http/https (prefer https), reject credentials/IP literals and private/loopback/link-local/reserved destinations after DNS resolution, recheck every redirect, cap redirects/time/bytes, validate content type, and resolve/fetch in a controlled adapter resistant to DNS rebinding. Provider-specific allowlists for captions. Do not disable TLS or checksum/package verification.
- Upload sniffing checks actual type, rejects unsafe filenames/path traversal, enforces quotas, treats archives as unsupported user material initially, bounds PDF/parser CPU and XLSX decompression. Store private files under generated keys outside web root; serve text safely and never execute macros/embedded scripts. Scan/quarantine policy before public multi-user uploads.
- Model inputs explicitly delimit untrusted source content. Instructions in a PDF/Drive note cannot override roles, request secrets or run tools. Model output is schema-validated and citations resolved against real excerpts; invalid or fabricated locators fail closed to retry/attention, not learner completion. Runtime tools cannot execute arbitrary shell or bypass source ownership.
- OAuth requests scoped Drive creation/upload plus verified source-reading access needed for app folders and manual drops; disclose broader read consent if required. `drive.file` is not assumed to expose arbitrary manually deposited files. Token encryption/rotation keys stay outside DB; disconnect/revoke supported. Resolve write parent from owned Collection folder, never arbitrary client IDs. Gmail remains read-only and does not authorize sending. Drive sync stays within configured folders and granted scopes.
- Do not log full answers, transcripts or study material by default. Audit IDs/timing/state and redacted error codes. Developer `docs/session-log.md` uses synthetic fixtures; production summaries live in private database records. Minimize model payload; disclose provider processing and retention.
- Voice capture is user initiated, browser permission shown; transcript editable. No background recording or retained raw audio by default. Browser speech may send audio to its own vendor; help text says so and typing remains available. Absence of a signal is uncertainty, not a competence diagnosis.
- Export/delete scope is user-specific; delete OAuth credentials, private blobs, embeddings if added, progress and pending jobs. Define configurable retention (default 30-day recoverable source archive, subject to actual privacy policy); backups have expiry and deletion handling. Make age/educational-use policy clear; no special claims about children's compliance without a separate design review.
- CI runs dependency/security scanners and independent review, documents severity decisions, keeps secrets out of fork PR workflows, and uses least-privilege deploy credentials. Public release stops on exploitable critical/high findings unless a documented exception is explicitly approved.

## Multilingual and Drive-write additions

Speech transcribe/synthesize endpoints enforce owner/session, CSRF, byte/duration/text/token/rate limits, signed/ephemeral delivery and no retained raw audio by default. Translate trusted UI catalogs and source-supported study text; untrusted source instructions cannot control translations, call folders/tools or change grading. Locale/RTL layout must not hide consent/error messages or misrepresent selected voice language. Drive writes are limited to bound folders, never share publicly or copy private transcript/progress into Drive receipts. Crash reconciliation validates identity/ownership before reusing a folder/file. See DRIVE_INGESTION for scope tradeoffs and INTERNATIONALIZATION for language/provider truthfulness.

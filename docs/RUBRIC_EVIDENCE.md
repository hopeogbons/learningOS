# Evidence for the user's three focus areas

Rubric supplied in chat: uniqueness 25%, scalability 25%, Codex usage 25%, presentation 25%. User owns presentation delivery. This package creates technical artifacts useful to the first three; it cannot guarantee a judging score.

| Area | Specific argument | Implementation proof | Honest limit |
|---|---|---|---|
| Uniqueness | Learner-selected titles become the denominator, with immutable revisions | Five cross-material selections → 0/5; late ingest no denominator drift | Selection itself isn't claimed novel research |
| Uniqueness | Citation-grounded micro-teaching and explain/apply checks across source types | Source click resolves actual page/cell/timestamp, private expected answer | Never fabricate source evidence |
| Uniqueness | Confidence calibration influences completion and resurfaces weak spots without over-testing | Confident-wrong vs correct-uncertain traces; coverage-aware completion; later due review | No measured efficacy claim without a user study |
| Uniqueness | This complete UI/workflow integrates Drive scope, multimodal sources and gentle review | Real recognizable supplied dashboard + working linked flows | Not a generic chatbot or feature-list demonstration |
| Scalability | Portable same-origin app with modular adapters, tenant isolation and stateless API | PostgreSQL concurrency/two-user tests; job restart; container portability | No global scale claim from one SQLite process |
| Scalability | Geographies/time/low bandwidth treated explicitly | DST/Lagos tests, UTF-8/RTL fixture, slow-link exercise, region choices | Translation/provider coverage checked separately |
| Scalability | Bounded queues/quotas and measured throughput | Recorded load hardware/data/p95/error/cost, before/after optimization | Targets are aspirations until benchmark passes |
| Codex usage | Persistent instructions and resume state produce all batches from one prompt | Master prompt, AGENTS, build-state transitions and genuine test traces | Documentation alone is insufficient use evidence |
| Codex usage | Native subagents/skills/image critique/review produce independent useful contributions | Actual invocation/results, design corrections and resolved review findings | Runtime API roles don't prove native subagents |
| Codex usage | Worktrees/MCP/hooks/automation/memory/voice assessed and used where supported | Feature-by-feature evidence with surface/version and exact boundary | Fallback/disabled stays labeled |

Record evidence under private development artifacts with synthetic study content. `docs/capabilities.md` is the feature claim ledger. `docs/validation-report.md` is the app release ledger. Do not make Git-tracked screenshots of real learner data. A recommended technical walkthrough can follow Collection → source locator → cross-material scope → confident-wrong check → successful coverage → due review → architecture/tests/Codex evidence; writing/slides/presentation coaching is outside the user's requested focus.

## Additional 25% scalability evidence

Show a real language switch (including Arabic RTL), a concept from the same original source taught/answered in another language with unchanged citation/progress, and a selected-language spoken exchange. Accompany the demonstration with all-ten catalog/speech matrix evidence; a selector by itself is insufficient. Show a UI upload placed in the correct Drive Collection folder, a directly dropped file discovered without UI upload, and one record after sync of the UI upload. Pair these with existing multi-user isolation, job recovery, load, timezone and low-bandwidth results. The screenshot is a requirements reference, not implementation proof.
